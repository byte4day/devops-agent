# Provider capability boundaries

Run `doctor` for installed CLI versions, authentication, account, and region. Run `plan` to see whether the chosen provider supports the detected execution model. A provider listed by the package is not necessarily authenticated or capable of every deployment mode.

Cloudflare, AWS, Alibaba Cloud, Vercel, Netlify, and GitHub have distinct resource models. Use the package's reported capabilities and current provider documentation before changing bindings, domains, environment variables, IAM, or infrastructure. `domain inspect HOST` performs public DNS and HTTPS/HTTP checks; `--provider` adds read-only hosting inspection where supported. `domain plan HOST --provider vercel --target PROJECT` proposes an additive attachment with strict remote ownership preconditions, but does not apply it or edit DNS. GitHub Actions `ci status` and `ci diagnose --run-id ID` are read-only; `ci setup` creates a local workflow only when project commands are clear; `ci repair` classifies evidence and leaves source edits to the assistant. A successful workflow run does not prove application health. Infrastructure managed by Terraform or OpenTofu should be changed through its plan/apply lifecycle, with appropriate approval. AWS CloudFormation has its own reviewed update path, separate from generic static deployment.

When auth is missing, report the provider's official interactive login path and let the user perform it locally. Never ask for credentials in chat. Do not install missing CLIs automatically.
